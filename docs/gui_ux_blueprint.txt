## 2. Current WPF Entry / Startup

| Area | Current File |
| :--- | :--- |
| WPF application entry point | `src/App.xaml` |
| Startup logic | `src/App.xaml.cs` |
| Main dashboard window | `src/UI/MainWindow.xaml` |
| Main dashboard code-behind | `src/UI/MainWindow.xaml.cs` |
| Dashboard state/controller | `src/UI/DashboardController.cs` |
| Fleet card view model | `src/UI/FleetCardViewModel.cs` |
| Shared UI theme resources | `src/UI/Themes/PsychoTheme.xaml` |
| Application/window icon | `assets/PsychoBuddy.ico` |

Startup behavior:

1. `App.xaml` generates the WPF entry point.
2. `App.OnStartup()` opens `MainWindow`.
3. `MainWindow` creates `DashboardController`.
4. The controller loads four empty/offline fleet slots.
5. The controller scans for available WoW clients.
6. No active bot logic starts until the user explicitly attaches and starts a client.

## 4. User Experience Flows

### 4.1 Startup Flow

`Launch PsychoBuddy.exe` → `App.xaml starts WPF` → `MainWindow opens` → `four empty/offline fleet slots display` → `client scan runs` → `technical log updates`

### 4.2 Attachment Flow

`Open WoW client(s)` → `Scan Clients` → `select available client` → `choose role/profile` → `Attach Selected` → `client appears in Fleet Monitor`

### 4.3 Runtime Control Flow

`Select attached fleet card` → `Start Selected` → `status changes to Running` → `Pause/Stop/Detach as needed`

### 4.4 Empty / No-Client Flow

If no WoW clients are found, the dashboard remains usable and shows four empty/offline slots:

- Awaiting Client
- Role: No Session
- Profile: No Profile
- Status: Offline
- Health/Mana values shown as blank placeholders rather than fake values

This confirms the UI is alive even before real attachment is available, without pretending that clients are connected.

## 5. Technical Component Mapping

| UI Element | Current WPF Component | Current Binding |
| :--- | :--- | :--- |
| Fleet Cards | `ListBox` + `UniformGrid` | `ObservableCollection<FleetCardViewModel> Fleet` |
| Available Clients | `ListBox` | `ObservableCollection<ClientBinding> AvailableClients` |
| Role/Profile Selectors | `ComboBox` | `RoleOptions`, `ProfileOptions`, `SelectedRole`, `SelectedProfile` |
| Attach/Start/Stop Buttons | `Button` click handlers | `DashboardController` workflow methods |
| Health/Mana Bars | `ProgressBar` | `FleetCardViewModel.HealthPercent`, `ManaPercent` |
| Technical Log | `TextBlock` inside `ScrollViewer` | `DashboardController.LogText` |
| Tactical Map | WPF `Canvas` placeholder | pending `Navigation` backend |
| Senses Toggle | `ToggleButton` | `DashboardController.ToggleSensesMode()` |
| Footer Stats | `StatusBar` / `TextBlock` | static + `StatusMessage` |

## 6. Aesthetic Guidelines

- **Palette:** Obsidian black, magma red/orange, burnished gold, parchment tan.
- **Typography:** Fantasy/Garamond-style title text; readable sans/mono for logs and technical data.
- **Panel style:** Heavy borders, dark semi-transparent cards, parchment log background.
- **Future skin pass:** Move inline styles into reusable `ResourceDictionary` files and replace placeholder symbols with real image assets.
